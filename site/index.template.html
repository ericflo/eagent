OPEN SOURCE. ONE GO BINARY.

Your agent.
Your call.

eagent runs a coding agent you already use (Codex, Claude Code, Antigravity, pi, or your own profile) in a terminal and stands between it and you. Your words reach the agent as written. eagent tells you what it is doing, clears the dialogs it gets stuck on, and asks you only what is yours to decide.

02 — BUILT FOR LONG SESSIONS

Sessions that
run for days.

A session can follow an agent through many turns, restarts and reconnects. The record, the dossier and the shape of each request keep that cheap, and nothing is ever lost.

ONE REDUCER, LIVE OR REPLAYED

Every event,
on disk.

A session is a directory of JSONL files in your project. Each line is one event, appended with fsync and never edited. The running process and eagent replay fold the same events with the same code, so replaying the log rebuilds the session exactly. eagent -c replays it and reattaches to the running agent.

Read the event schema

A FRESH START WITH A MAP

Long conversations.
Nothing shortened.

When the conversation fills half the model’s context window, it restarts from a dossier. The same model writes it after reading the whole record: where the session stands, and a map of file:line places for every topic that matters. The record is kept whole, and eagent goes back to the lines the map names when an old subject comes up.

CHEAP TO LOOK

Every call reuses
the one before.

The system prompt and tool list never change during a run, the conversation only grows, and what changes from call to call sits in a short tail at the end. Every call uses one model at one reasoning effort, so the provider’s prompt cache keeps hitting. A look where nothing is worth saying costs a cached read and a few output tokens.

Read why looks are cheap

WHILE YOU ARE AWAY

Standing orders
and timers.

A standing order makes eagent send the agent on at every stop, toward what is still missing, and decide its questions the way you would. When the deadline passes, eagent stops nudging and reports what happened. Timers wake eagent later with a note it left itself.

03 — ONE MODEL PER PRESET

Pick eagent’s
own model.

eagent’s loop runs on one model, with an optional fallback route for when the first is unroutable. Each preset names one model. With no preset, eagent uses {{DEFAULT_MODEL}}. A local or custom server works too: eagent servers add URL probes it and registers it.

The agent keeps its own model. Choose it with --relay-model, or change it in a session with /model sonnet high.

THE AGENTS

Four built in. Add your own.

Each agent runs in a terminal eagent owns, named eagent-relay-<session>-<name> on a private tmux socket. What it says is read from its own transcript. /switch claude hands the work to another agent in the same folder, with a brief of your instructions and the last report. A custom profile goes under relay.profiles in the project config. A new kind of agent is one Go file that implements the agent interface, plus a line in the built-in profiles.

05 — ON YOUR PHONE

Every session
is a thread.

With FinaleChat, each session appears on your phone with its messages, questions with buttons, the agent’s screen and settings. You can start a new session there too. Messages land quietly. Questions always buzz, and so does finished work or a blocked agent. /notify-done buzzes when the current turn ends.

Keep eagent serve running in the project so the phone can start sessions and bring a finished one back when you reply.

A LITTLE MORE CONTEXT

Questions.

Read the README
Does eagent still do the work itself?+

No. Earlier versions ran three models: an orchestrator that planned and could do the work with its own shell and file tools, task workers it delegated to, and a narrator. That design is gone. eagent has no task workers and no tools that touch the project; the agent you run does the work, and one model loop does the watching and the talking. Sessions and config files from the earlier version still load. Old sessions list, show, export and replay as before, and resume from a dossier written from their files. eagent doctor lists what an old config file carried over.

What does it cost?+

eagent is free, open-source software under the MIT license. You pay your provider for eagent’s own model, and the agent runs on its own account as it would without eagent. The web page shows the session’s token usage and cost. Looks where nothing changed make no model call at all.

Can I use a local model?+

Yes. eagent servers add URL probes a local or custom server’s models and API kinds and registers it, and eagent servers use ID points eagent’s model at it. eagent speaks OpenAI Chat Completions, OpenAI Responses and Anthropic Messages.

Where does my session live?+

Under .agents/eagent/sessions/ in your project, as JSONL files. There is no database to run. eagent’s model provider receives the conversation it needs. With FinaleChat on, the session is mirrored to your phone and archives are published to your account; eagent artifact disable turns the archives off and EAGENT_FINALECHAT=off turns all of it off.

Is the agent sandboxed?+

No. The agent runs on your machine as you, with whatever permissions its profile gives it, and eagent answers its startup dialogs so that it can go ahead. Run it in a workspace and environment you are comfortable letting it change.

What happens if eagent’s model fails?+

Your messages still reach the agent, since forwarding happens before any model call. A failed call is retried at once, then after a minute, then 5, 15 and 30 minutes, then hourly. After the second failure eagent tells you it cannot reach its model. A configured fallback route takes over when the first is unroutable, for example with a bad key or no credits.

Can I change how eagent talks?+

Yes. Ask for more or fewer updates and it does that from then on. eagent prompts export copies its prompts into the project, where you can edit them, and persona in the config replaces its voice. quiet_seconds sets the longest silence while the agent works.
